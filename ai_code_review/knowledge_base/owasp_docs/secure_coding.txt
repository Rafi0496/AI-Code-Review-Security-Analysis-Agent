# Enterprise Secure Coding Standards, Clean Architecture & Code Review Master Reference

## 1. Executive Summary & Core Security Tenets
Secure software development requires integrating defensive engineering into every phase of the Software Development Lifecycle (SDLC). Writing secure code is not merely avoiding known syntax mistakes; it is designing resilient, observable, and maintainable systems that fail safely when attacked or degraded.

---

## 2. Universal Secure Coding Tenets

### 2.1 Never Trust Input (Zero Trust Input Validation)
- All data originating from outside the application boundary (HTTP query params, headers, JSON bodies, uploaded files, environment variables, message queues, third-party APIs) must be validated against strict schemas (Pydantic, Zod, Joi, Bean Validation).
- Prefer Allow-lists / Whitelists over Deny-lists.

### 2.2 Context-Aware Output Encoding
- Encode data immediately before rendering or sending to interpreters (HTML, SQL, Shell, XML, LDAP).

### 2.3 Cryptography & Secrets Management
- Never hardcode secrets, API keys, passwords, or private certificates into source repositories.
- Use memory-hard key derivation functions (Argon2id, Bcrypt) with appropriate work factors for credentials.
- Use AES-256-GCM or ChaCha20-Poly1305 for authenticated symmetric encryption with unique nonces.
- Use cryptographically secure random number generators (`secrets` in Python, `crypto.randomBytes` in Node.js, `SecureRandom` in Java).

### 2.4 Structured Error Handling & Safe Logging
- Catch specific exception types. Never write bare `except:` or empty catch blocks.
- Strip sensitive PII, credit cards, passwords, and tokens before logging.
- Sanitize log messages against CRLF Injection (`\r`, `\n`).

### 2.5 Software Supply Chain & Dependency Health
- Generate and verify Software Bills of Materials (SBOMs - CycloneDX / SPDX).
- Pin dependencies with exact cryptographic SHA-256 hashes.
- Enforce automated Software Composition Analysis (SCA) scanning in CI/CD.

## 3. Comprehensive Code Review Security Checklist

| Checkpoint | Verification Requirement | Priority |
|------------|--------------------------|----------|
| **Authentication** | Passwords hashed with Argon2id/Bcrypt; MFA supported; session IDs 128+ bit entropy. | Critical |
| **Authorization** | Every endpoint verifies role AND object-level ownership (BOLA / IDOR defense). | Critical |
| **SQL & Database** | 100% of database queries use parameterized prepared statements or ORM builders. | Critical |
| **Subprocess / Shell**| No `os.system()`, `eval()`, `exec()`, or `shell=True`. Arguments passed as discrete token arrays. | Critical |
| **Input Validation** | All inputs typed and validated with regex/schema before processing. | High |
| **Data Protection** | Sensitive data encrypted at rest (AES-256-GCM); TLS 1.3 enforced in transit. | High |
| **Session Cookies** | Cookies configured with `Secure; HttpOnly; SameSite=Strict`. | High |
| **Error Handling** | No internal stack traces or environment variables exposed in HTTP error responses. | Medium |
| **Code Architecture** | Functions have single responsibility (SRP); max 50 lines; low cyclomatic complexity. | Medium |
