# OWASP A05:2021 – Security Misconfiguration Master Reference

## 1. Executive Summary & Overview
Security Misconfiguration ranks #5 in the OWASP Top 10 (2021). With the growth of highly configurable cloud platforms, container orchestration (Kubernetes), microservice service meshes, and web frameworks, misconfigurations have become one of the most prevalent attack vectors.

Common manifestations include:
- Leaving default usernames and passwords enabled (e.g. `admin:admin`, `root:root`)
- Enabling debugging flags in production (Django `DEBUG=True`, Flask `debug=True`, Express verbose stack traces)
- Overly permissive Cross-Origin Resource Sharing (CORS) configurations (`Access-Control-Allow-Origin: *` with credentials)
- Missing defensive HTTP response headers (CSP, HSTS, X-Content-Type-Options, X-Frame-Options)
- Publicly accessible cloud storage buckets (AWS S3 public read/write, Azure Blob public access)
- Unnecessary ports, services, sample applications, and documentation pages left enabled in production

## 3. Deep Technical Analysis & Vulnerability Patterns

### 3.1 Framework Debug Mode Enabled in Production (CWE-215 / CWE-209)
Running a framework with `DEBUG = True` leaks source code snippets, database queries, environment variables, secret keys, and interactive REPL consoles (e.g. Werkzeug debugger PIN exploit) directly to attackers upon any unhandled exception.

#### Vulnerable Implementation (Python / Django):
```python
# VULNERABLE: settings.py with hardcoded production debug
DEBUG = True # High vulnerability: Exposes interactive traceback & config variables
SECRET_KEY = 'django-insecure-default-key-never-use-in-production'
ALLOWED_HOSTS = ['*'] # Permissive host header allows cache poisoning
```

#### Remediated Secure Implementation (Django):
```python
# SECURE: Environment-driven strict configuration
import os

DEBUG = os.getenv("DJANGO_DEBUG", "False").lower() in ("true", "1")
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"] # Mandatory environment variable
ALLOWED_HOSTS = os.environ["DJANGO_ALLOWED_HOSTS"].split(",")

# Cookie & Session hardening
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SESSION_COOKIE_HTTPONLY = True
SECURE_HSTS_SECONDS = 31536000 # 1 Year HSTS
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SECURE_CONTENT_TYPE_NOSNIFF = True
```

### 3.2 Overly Permissive CORS Headers (CWE-942)
Cross-Origin Resource Sharing (CORS) is a browser mechanism that restricts scripts running in one origin from reading responses from another origin. Misconfiguring CORS allows malicious third-party websites to steal sensitive user data via the victim's browser.

#### Vulnerable Implementation (Node.js / Express):
```javascript
// VULNERABLE: Wildcard origin with credentials enabled or reflection of any Origin header
app.use((req, res, next) => {
    res.header("Access-Control-Allow-Origin", req.headers.origin); // Reflects any origin!
    res.header("Access-Control-Allow-Credentials", "true"); // Allows authenticated requests from attacker site
    res.header("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE,OPTIONS");
    next();
});
```

#### Remediated Secure Implementation (Node.js / Express):
```javascript
// SECURE: Strict explicit origin whitelist
const cors = require('cors');

const ALLOWED_ORIGINS = new Set([
    'https://app.enterprise.com',
    'https://admin.enterprise.com'
]);

const corsOptions = {
    origin: (origin, callback) => {
        // Allow requests with no origin (like server-to-server or mobile apps)
        if (!origin || ALLOWED_ORIGINS.has(origin)) {
            callback(null, true);
        } else {
            callback(new Error('Blocked by CORS policy: Origin not allowed'));
        }
    },
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'DELETE'],
    allowedHeaders: ['Content-Type', 'Authorization', 'X-Requested-With']
};

app.use(cors(corsOptions));
```

## 4. Hardening Checklist & Configuration as Code
1. **Automated Infrastructure Hardening**: Use Terraform, Ansible, or CloudFormation templates with built-in security linters (`checkov`, `tfsec`).
2. **Remove Unused Dependencies and Endpoints**: Disable Swagger UI / OpenAPI docs in production environments.
3. **Continuous Compliance Scanning**: Use tools like OpenSCAP, AWS Security Hub, or CIS Benchmark scanners.
4. **Enforce Strict Content Security Policy (CSP)**: Disallow `unsafe-inline` and `unsafe-eval` scripts.
